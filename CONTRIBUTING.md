# Contribute

Thanks for taking the time to contribute !

## Translations

[Tracim](https://www.tracim-teamwork.com/) translations are done through [Weblate](https://weblate.org/tracim/tracim/).

To contribute to translations, simply head over to the [Tracim Weblate website](https://weblate.org/tracim/tracim/) !

## Forum

Paying users get professional support services. A forum is also available for community support at https://public-community.tracim.fr/.

Helping other users would be of a great value for the Tracim Community !


## Code

### Feature idea or bug report : open an issue !

Before starting coding, please submit your idea using the project issues !

Before creating a new issue, please check that there isn't any existing one.  
If there is no issue similar to yours, feel free to create an issue and follow the template.

### Develop a new feature

Do you want to develop a new feature ? Great !   
Let's start:

1. Open an issue with the feature template.
2. Create a branch from `develop` named `feat/<your ticket title>`.
3. Start coding!

### Install a local Tracim instance

See the [getting started for developper](docs/developer/setup_env/getting_started.md) documentation to see how to build and
run [Tracim](https://www.tracim-teamwork.com/) on your system.

### Test

See [testing backend](docs/contribution/code/tests_for_backend.md) and
[testing frontend](docs/contribution/code/tests_for_frontend.md) to see how to test [Tracim](https://www.tracim-teamwork.com/) and
your developments.

### Commit to the repository

You need to sign every commit you make with the `-s` arg of `git commit` command.  
See [git signature](https://git-scm.com/docs/git-commit#git-commit--s).   
This will prove that you are the author of the commit, and you have accepted the licenses
([MIT](https://opensource.org/licenses/MIT), [LGPLv3](https://www.gnu.org/licenses/lgpl-3.0.html)
and [AGPLv3](https://www.gnu.org/licenses/agpl-3.0.html)) and [Developer Certificate of Origin](/docs/_assets/licences/DCO).

Also, please follow our recommandations: [before_push.md](/docs/contribution/code/before_push.md).

### Create a pull request

Once you have finished your development, and you want to merge it on the
`develop` branch, please create a pull request.  
The pull request must have an explicit title. For example: `feat(frontend): <your feature>`.  
Once the pull request is created, follow the template.
